# US-22: Polyglot Contract Enforcement

*Paths and seams for this (sub)story. `ADR-005`: integration is implicit here — a path this story
cannot walk with one feature is a **seam FR** of the story, and its test is written red first. Where
a related (sub)story is unbuilt the test is still written now, as `xfail(strict=True)` naming the
blocker. The story is finished when those tests are green.*

*Requirement ids of the shape `INT-US-NN FR-N` are frozen history: they name delivered requirements
cited by tests and design documents, and renaming them would break the citations without changing
what was built. No new one is ever minted.*

## Base Story
* **Status:** ⬜ Pending — migration `INT-US-22-MIG` discharged 2026-08-17; no path
  waits on this contract, so closure is a scope decision
* **Integration Description:** US-22 proves a Python microservice did not break a Rust worker's
  REST/gRPC contract. It holds **two** closed capabilities — `A-VAL-01` (Protocol/Schema Analyzers)
  and
  `C-VAL-04` (Traceability Matrix Check) — with `A-VAL-04` (Rust PyO3 validations) unbuilt.
* **Verifiable Proof:** P-2 by
  `tests/e2e/capabilities/assurance/test_validation_pipeline_e2e.py::TestCodeValidationPipeline::test_c09_traceability_enforced_in_code_validation_pipeline`
  — one real `sw check` run over a real project, failing on an unmapped FR-39 and passing once its
  `@trace` is added, with a mutant behind each half. **P-1 cannot have a spanning test today, and that is the
  finding.** Measured 2026-08-19: with a real `.proto` on disk and code that does not match it,
  `sw check --level code` reports `C13 SKIP — Missing 'protocol_schema'`. Nothing in `src/` ever
  produces that key; the executor builds a rule's context from `ast_payload` alone, and no pipeline
  or handler passes a parsed protocol schema. So `A-VAL-01` FR-5's stated outcome — *"emits ERRORs
  on missing/mismatched signatures"* — is unreachable in a real run, and its unit test proves the
  rule against a context that is never constructed. The parsers (FR-1 to FR-4) are real and
  unit-proven; the join to validation is missing, which is a defect in delivered work and is filed as
  [`TECH-066`](../features/topic_07_technical_debt/TECH-066/TECH-066_design.md) rather than tested
  around. A test written today could only assert the `SKIP`, which would record the defect as the
  intended behaviour. Both also by `check_fr_coverage.py A-VAL-01` and
  `... C-VAL-04`, which exit 0.

### Path List (`ADR-005`)

| # | Path | Span | Owner | Runnable today | Blocker |

**Two closed capabilities that do not meet yet.** `A-VAL-01` analyses protocol schemas; `C-VAL-04`
compares spec requirements against `@trace` tags in test code. Neither reads the other — the
cross-service comparison P-3 describes needs the deep contract checking `A-VAL-04` is for, and that
is
unbuilt. Third story in this migration where two closed features coexist without a runnable path
between them (`US-6`, `US-19`, and now `US-22`), which is worth noting as a pattern rather than an
accident: a story's capabilities are chosen for the journey, and the journey usually needs the piece
that is missing.

**`INT-US-22-MIG` is discharged, and every deferred path now names the ticket that owns it.**
No path waits on this contract. Whether it closes is a scope decision under `ADR-004`, which
reopened the one `CLOSED EMPTY` of this shape: a contract over closed capabilities is not empty
while their cross-feature paths are unproven.
