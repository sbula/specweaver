# US-06: The Remote Dashboard (Tablet on a Train)

*Paths and seams for this (sub)story. `ADR-005`: integration is implicit here — a path this story
cannot walk with one feature is a **seam FR** of the story, and its test is written red first. Where
a related (sub)story is unbuilt the test is still written now, as `xfail(strict=True)` naming the
blocker. The story is finished when those tests are green.*

*Requirement ids of the shape `INT-US-NN FR-N` are frozen history: they name delivered requirements
cited by tests and design documents, and renaming them would break the citations without changing
what was built. No new one is ever minted.*

## Base Story
* **Status:** ⬜ Pending — migration `INT-US-06-MIG` discharged 2026-08-17; no path
  waits on this contract, so closure is a scope decision
* **Integration Description:** US-6 is the "tablet on a train" story. It holds **two** closed
  capabilities — `C-FLOW-02` (router-based flow control) and `E-UI-02` (web dashboard) — and the
  bridge between them, `D-UI-01` (`sw serve` Core Orchestration API), is unbuilt.
* **Verifiable Proof:** the seam by
  `tests/integration/interfaces/api/test_routing_reaches_the_dashboard.py` — a real `PipelineRunner`
  routes past a step into a real SQLite store, and the run and its `step_routed` row are read back
  through the real HTTP app. Four mutants die on four different sides of it: the engine not writing
  the row, the page not reading the audit log, the list not reading the store, and the jump
  resolving and being thrown away. P-1 and P-2 individually by `check_fr_coverage.py C-FLOW-02` and
  `... E-UI-02`, both exit 0 with every FR behind a killed mutant; the router's own parse, validate
  and jump are at integration tier in
  `tests/integration/core/flow/engine/test_router_integration.py`.

**Two closed capabilities and still no runnable cross-feature path, which is the finding.** The
dashboard talks to the state store directly and the router runs inside the engine; nothing joins
them
today. `D-UI-01` is that join, and it is unbuilt — so P-3 and P-4 are retired to it, and it
declares them as its own FRs.

`E-UI-02` shipped with a design declaring **no requirements at all**. It now has three, written from
why it exists rather than from what the code does (§3.2c), and FR-1 needed a new test before it
could
be declared: its mutant survived because the runs page always rendered and the only assertion was
that
the words "Pipeline Runs" appeared.

**`INT-US-06-MIG` is discharged, and every deferred path now names the ticket that owns it.**
No path waits on this contract. Whether it closes is a scope decision under `ADR-004`, which
reopened the one `CLOSED EMPTY` of this shape: a contract over closed capabilities is not empty
while their cross-feature paths are unproven.
